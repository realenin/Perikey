# PeriKey · 家庭 Wi-Fi 周期密钥轮换与自动分发系统

> **Peri**odic **Key** rotation & distribution for home Wi-Fi —— 让定期更换 WiFi 密码不再需要逐台重连，并削弱「设备越多越易被抓包破解」的助攻效应。

## 0. 项目定位与作者说明

> 这是一个由**非网络安全专业背景的普通家庭用户**发起的探索性项目，目前处于 **概念验证 / RFC 草案** 阶段。

- **为什么会有它**：作者家中约 25 台终端 + 上百台智能家居设备，基于 Kali 实测发现「设备越多越易被抓包爆破」，且手动换密要逐台重连，痛感真实。
- **它现在是什么**：一份把朴素想法规范化的**方案设计 + 可运行的概念原型**，用于论证可行性、抛砖引玉，**不是可直接部署的安全产品**。
- **它不宣称什么**：协议与密码学零件均非首创（DPP / 802.1X / PPSK 早已存在），本项目只尝试把这套能力做成普通家庭用户用得上的管理层。
- **作者的态度**：欢迎任何专业人士指正、补充与贡献——尤其是路由固件、hostapd、IoT 协议方向。这个项目若能帮到有同样痛点的人，便是它最大的价值。

## 1. 一句话定位

家庭网络中，路由器对网内所有设备使用**同一个接入密码（PSK）**。使用者希望定期更换该密码以提升安全，但手动在几十上百台设备上重连极其繁琐；同时，网内设备越多，空气中可捕获的握手包越多，越容易被离线爆破。PeriKey 让路由器在「换密前」先与每台已连设备**握手约定新密码**，重启（或热重载）后全员用新密码自动重连；并对不兼容新加密格式的老设备单独下发**独立长密码**。使用者仅在带二次验证（2FA）的窗口统一管控。

## 2. 背景与真实痛点

使用者基于 Kali OS 实测观察：

- 通过抓包可快速获取 WiFi 握手哈希包，再用 GPU 离线爆破他人网络密码，效率极高。
- **关键观察：被破解目标网络中已接入设备越多，抓包成功率越高**——更多设备意味着更多（重）关联产生的四次握手包，攻击者只需捕获其中任意一个即可爆破出那个**全网共用**的 PSK。
- 因此「设备密度」在单 PSK 模型下反而放大了风险：一台被爆，全网失守；设备越多，暴露面越大。

## 3. 使用者的原始想法（已规范化）

| 编号 | 想法 | 规范化 |
|------|------|--------|
| I | 换密码要逐台重连，太繁琐 | 需要**自动分发**新密码，免除逐台人工重配置 |
| II | 已连设备能否经协议握手，约定「路由器重启后改用新密码接入」 | **换密前预约定（Pre-Rotation Agreement）**：用当前仍有效的旧连接作安全通道，先分发再重启，化解鸡生蛋 |
| III | 老设备不兼容先进 WPA 格式，强行升级格式又接不进；不如给老设备很长的独立密码 | **老设备独立长密码（PPSK 思路）**：不逼全网降级，单台破解成本被拉长 |

附加要求：使用者在路由器一个**带 2FA** 的窗口设置/更换网络接入密码，确保确为本人操作。

## 4. 方案总览

```
使用者 (2FA 门控)
   │ 设置 NewPSK（或触发周期轮换）
   ▼
Controller（路由器守护进程）
   │ ① 换密前，对每台【已连接】设备发起握手
   │ ② 用每台设备的「设备小秘密 DSecret_i」加密下发 NewPSK
   │ ③ 设备本地存好 NewPSK 并回 ACK
   ▼
路由器 重启 / 热重载 hostapd（应用 NewPSK）
   ▼
各设备 用本地已存的 NewPSK 自动重连（无需人工）
   └─ 老设备：走各自独立长密码，不参与主密码轮换
```

- **鸡生蛋如何化解**：分发动作发生在「旧密码仍有效」的窗口内，利用既有的已认证连接作为安全通道，因此不存在「没新密码就连不上、连不上就收不到新密码」的死锁。
- **老设备处理**：单独分配长独立密码（PPSK），既不拖累主网络采用先进加密格式，又抬高单台被爆成本。

## 5. 为什么这能成立（核心论证）

1. **对抗使用者的 Kali 威胁**：外部攻击者只抓到旧握手包、尚未进网 → 读不到 LAN 内流量 → 拿不到预约定下发的 NewPSK；且旧握手包在轮换后即失效，攻击者必须每个周期重新抓包+爆破，**成本被周期倍增**。
2. **分发通道的强化**：若明文下发 NewPSK，一个已持旧密码混入的攻击者可读到。用设备首次联网时建立的 `DSecret_i` 逐台加密下发即可封堵（详见 `protocol.md`）。即便不做这层，对使用者的主威胁仍有效。
3. **无需新密码学**：`hostapd` 的 `wpa_psk_file` 原生支持同 SSID 多 PSK；周期仅改变「约定/下发的密码值」并热重载，无需整机重启。

## 6. 可行性结论（详见 [`docs/feasibility.md`](docs/feasibility.md)）

| 维度 | 判定 |
|------|------|
| 自动分发新密码、免逐台重连 | ✅ 可行（换密前预约定 + 热重载） |
| 鸡生蛋问题 | ✅ 已由「旧连接作通道、先约定后重启」化解 |
| 老设备独立长密码 | ✅ 可行（PPSK / `wpa_psk_file`） |
| 使用者 2FA 门控 | ✅ 可行（管理平面与数据平面分离） |
| 削弱「设备密度→易破解」 | ✅ 有效（轮换缩窗 + 老设备隔离） |

## 7. 新颖性定位（诚实声明）

本协议在密码学/协议层**并非首创**。已有先例：

- **PPSK / `wpa_psk_file`**（OpenWrt 原生、`fakuivan/hostapd-slppsk`、`RADIUSdesk`）：同 SSID 每设备不同 PSK。
- **Wi-Fi DPP / EasyConnect**：公钥无密码入网 + 重配置（但消费路由少支持；2025 DEF CON 33 披露 PPK 单点失效）。
- **WPA3-Enterprise / 802.1X**：每设备证书（企业级，消费路由多不支持）。
- **WPA3-SAE**：抗离线字典攻击、前向保密。

**本项目的真实增量**：把你这套「换密前预约定 + 老设备独立长密码 + 2FA 门控」的**家用产品化管理层**做出来，并给出可在普通 OpenWrt 硬件跑的参考实现。协议零件都现成，但「让普通家庭用户用得上、且专门对冲设备密度带来的抓包风险」这一层是实空白。详见 [`docs/related-work.md`](docs/related-work.md)。

## 9. 快速验证

无需硬件或第三方库，纯 Python 标准库即可运行：

```bash
cd prototype
python3 demo.py
```

原型演示：设备首次联网建立 `DSecret` → 使用者设新密码 → 路由器**换密前**逐台加密下发 → 模拟「重启」应用新密码 → 设备用本地新密码自动重连 → 验证「仅持旧握手包的外部攻击者」拿不到新密码；并演示老设备独立长密码路径。
