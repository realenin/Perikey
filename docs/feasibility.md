# 可行性论证（Feasibility Analysis）

> 回答使用者最关心的问题：**这个想法能不能实现？** 结论先行，再逐项拆解。本文基于使用者最新澄清的真实模型。

## 0. 结论

**目标完全可行，且比「每设备独立 PKI」更轻、更易在消费硬件落地。** 使用者的核心机制——「换密前先与已连设备握手约定新密码，再重启/热重载，全员自动重连」——在现有技术栈上可完整实现，无需发明新密码学。

| 维度 | 判定 | 依据 |
|------|------|------|
| 自动分发新密码、免逐台重连 | ✅ | 换密前预约定（Pre-Rotation Agreement）+ `hostapd` 热重载 |
| 鸡生蛋问题 | ✅ 已化解 | 分发发生在「旧密码仍有效」窗口，旧连接即安全通道 |
| 老设备独立长密码 | ✅ | PPSK / `wpa_psk_file` 原生支持 |
| 使用者 2FA 门控 | ✅ | 管理平面与数据平面分离 |
| 削弱「设备密度→易破解」 | ✅ | 轮换缩窗 + 老设备隔离，使单握手包价值骤降 |

---

## 1. 使用者真实模型的规范化

- **M0（单一共享密钥）**：全网设备使用同一个 PSK = `K`（使用者设定）。
- **M1（换密前预约定）**：路由器在应用新密码 `K'` 之前，对每台**已连接**设备发起握手，将 `K'` 安全下发给设备；设备本地存 `K'` 并回 ACK。
- **M2（重启/热重载应用）**：路由器切换为 `K'`（使用者原话为「重启」，实现上可用 `hostapd` 热重载等效达成，避免全网约数十秒断网）。
- **M3（自动重连）**：设备凭本地已存的 `K'` 自动重连，无需人工。
- **M4（老设备独立长密码）**：不兼容先进 WPA 格式的老设备，分配**独立、很长的密码** `L_i`，不参与主密码 `K` 的轮换；既不逼全网降级加密格式，又抬高单台被爆成本。
- **M5（2FA 门控）**：设置/更换 `K` 的窗口需二次验证，确保是本人操作。

## 2. 使用者实测威胁是否成立？

使用者在 Kali 下观察：**目标网络接入设备越多，抓包成功率越高，GPU 爆破越容易。**

机制分析（与使用者观察一致）：

- 单 PSK 模型下，网络上**任意一台**设备（重）关联产生的四次握手包，被捕获后都可用于离线爆破出那个**全网共用**的 `K`。
- 设备越多 → 握手包生成频率越高（设备漫游、重连、断电恢复）→ 攻击者捕获到至少一个 handshake 的机会越大。
- 因此「设备密度」在单 PSK 下确实放大了风险；使用者「一台被爆→全网危险」的担忧成立。

**PeriKey 的对冲逻辑**：

1. 轮换使 `K` 的有效窗口从「永久」缩为「一个周期」。攻击者即便爆出旧 `K`，也仅在当前周期有效；下一周期需重新抓包+爆破。
2. 老设备用独立长密码 `L_i`，其被爆不影响主网络 `K`，且长密码本身抬升爆破成本。
3. 外部攻击者（仅持捕获的握手包、尚未进网）读不到 LAN 内流量，因此拿不到预约定下发的 `K'`。

## 3. 鸡生蛋问题：使用者的解法是对的

原始疑问：「没新密码就连不上，连不上就收不到新密码。」

使用者的解法（M1+M2 顺序）：**先约定，后切换**。分发 `K'` 发生在旧密码 `K` 仍有效期间，利用既有的已认证连接作为安全通道。因此不存在死锁。这比引入独立 PKI/DIK 更轻量，且完全满足需求。

**唯一需补硬的点（强化，非推翻）**：`K'` 在 LAN 内下发时若明文，则一个**已持旧 `K` 混入网络**的攻击者也能读到。解决：用每台设备首次联网时建立的**设备小秘密 `DSecret_i`** 对 `K'` 做逐台信封加密。即便省略这层，对使用者的主威胁（外部只抓包、未进网）依然有效——因为该攻击者读不到 LAN 流量。故 `DSecret` 是对「更强的已入网攻击者」的加固，属可选增强。

## 4. 老设备兼容性（M4）为什么合理

使用者指出：WEP/WPA2/WPA3 等格式不被部分老设备支持，强行全网用先进格式会导致老设备接不进；但给全网设一个复杂密码又增加使用难度。

M4 的应对：

- 主网络用先进格式 + 轮换主密码 `K`（由 PeriKey 自动分发，用户无感）。
- 老设备走**独立长密码 `L_i`**（PPSK），格式按老设备能力选，与主网络隔离。
- 效果：主网络不因老设备而降级；老设备的破解成本因其长密码而显著升高；即便 `L_i` 被爆，主网络 `K` 不受影响。

## 5. 硬件与实现可行性

| 能力 | 可行性 | 证据 |
|------|--------|------|
| 同 SSID 多 PSK（主密码 + 老设备独立密码） | ✅ | `hostapd` `wpa_psk_file` 原生支持 |
| 无数据库按主密码派生 | ✅ | `fakuivan/hostapd-slppsk` 已验证 |
| 热重载切换密码（替代整机重启） | ✅ | `hostapd` 重载配置即生效，无需重启 |
| 设备小秘密 `DSecret_i` 信封加密下发 | ✅ | 标准 AES/HMAC，设备端轻量存储 |

**采用壁垒（诚实告知）**：需路由器跑 **OpenWrt**（或支持自定义 `hostapd` 配置）。原厂消费固件多封闭，无法直接落地；但 OpenWrt 可刷硬件存量大，目标市场成立。

## 6. 真实风险与边界

1. **错过的设备**：预约定时离线的设备收不到 `K'`。需定义容错：旧 `K` 宽限期、或离线设备回网后走「引导 SSID + 2FA 重新约定」。
2. **`DSecret_i` 存储**：设备端需安全保存 `DSecret_i`；低端 IoT 可能无安全存储，需退化为「首次联网时由用户重新授权」。
3. **已入网攻击者的残留**：若攻击者在轮换前已持 `K` 并建立会话，轮换可将其踢出（强制重认证），但其若已植入后门则非本系统职责范围。
4. **MAC 随机化**：若用 MAC 绑定 `DSecret`，手机随机 MAC 会破坏绑定 → 应用设备身份指纹而非 MAC 作 `DeviceID`。

## 7. 综合判定

| 判定项 | 结果 |
|--------|------|
| 想法能否实现 | ✅ 能，无需新密码学 |
| 使用者模型是否需推翻 | ❌ 否；仅需一处加固（`DSecret` 加密下发） |
| 是否协议级首创 | ❌ 否（PPSK / DPP / 802.1X 已有） |
| 是否有真实创新空间 | ✅ 有（家用产品化管理层 + 专门对冲抓包密度效应） |

**最终结论**：这是一个**工程产品化创新**，能解决使用者真实痛点，技术上站得住，值得立项。优先产出 OpenWrt 守护进程对接 `wpa_psk_file` 的最小可用实现（见 `roadmap.md`）。
