# 协议规范（Protocol Specification）

> 本协议实现使用者的核心想法：**换密前先与已连设备握手约定新密码，再重启/热重载，全员自动重连**；并对老设备单独下发独立长密码。

## 1. 记号（Notation）

| 符号 | 含义 |
|------|------|
| `K` | 当前主网络密码（PSK），使用者经 2FA 设置 |
| `K'` | 下一个（轮换后的）主网络密码 |
| `L_i` | 第 `i` 台老设备的独立长密码（不参与轮换） |
| `DSecret_i` | 第 `i` 台设备的「设备小秘密」，首次联网时建立，仅用于安全下发 `K'` |
| `DeviceID_i` | 设备唯一标识（优先设备身份指纹，非 MAC，抗随机化） |
| `epoch` | 轮换计数，每次换密 +1 |
| `Enc(k, m)` / `Dec(k, m)` | 信封加密（生产用 AES-256-GCM，密钥 `k=HKDF(DSecret_i)`） |

## 2. 阶段 0：注册（Enrollment，仅首次）

1. 使用者像今天一样，在设备上输入 `K` 联网。
2. 连接成功后，设备本地生成随机 `DSecret_i`，并通过**已建立的加密 WiFi 会话 / 路由器本地 HTTPS** 发送给 Controller。
3. Controller 存储 `(DeviceID_i, DSecret_i, epoch, K)`；设备本地保存 `(DeviceID_i, DSecret_i)`。
4. 老设备在此阶段额外领取独立长密码 `L_i`，写入 `hostapd` 的 `wpa_psk_file` 独立条目。

> `DSecret_i` 仅用于「未来密码的安全下发」，不是 WiFi 接入密钥本身。这一步是可选的加固层（见 `feasibility.md` §3）。

## 3. 阶段 1：轮换触发

- 使用者经 **2FA 门控**的管理窗口设置 `K'`；或周期策略触发。
- Controller 计算 `epoch' = epoch + 1`。

## 4. 阶段 2：换密前预约定（Pre-Rotation Agreement，核心）

对每台**当前已连接**的设备，在旧密码 `K` 仍有效期间：

```
Controller ──ROTATE_PROPOSE{epoch', ct=Enc(DSecret_i, K'), apply=reboot}──▶ Device_i
Device_i   ──ROTATE_ACK{epoch'}───────────────────────────────────────────▶ Controller
```

- 设备用 `DSecret_i` 解密得到 `K'`，**本地存储**，随后回 ACK。
- 若无 `DSecret_i`（未注册），退化为：在已加密的 WiFi 会话内明文下发 `K'`（对外部被动攻击者仍安全，见威胁模型）。

**鸡生蛋化解**：本阶段全部发生在旧连接之上，故不存在「无新密码则无法通信」的死锁。

## 5. 阶段 3：应用（Apply）

- Controller 切换为 `K'`。使用者原话为「重启」，实现上可等价用 `hostapd` **热重载**（避免全网约数十秒断网）；是否整机重启由部署策略决定。

## 6. 阶段 4：自动重连（Reconnect）

- 各设备凭本地已存的 `K'` 自动重连，无需人工。
- 老设备持续使用 `L_i`，不参与本轮轮换。

## 7. 阶段 5：容错与撤销

| 情形 | 处理 |
|------|------|
| 预约定时设备离线、未收到 `K'` | 旧 `K` 保留宽限期；设备回网后走「引导 SSID + 2FA 重新约定」 |
| `DSecret_i` 丢失/设备重置 | 重新执行阶段 0（使用者 2FA 授权） |
| 撤销某设备 | 将其 `DeviceID` 从注册表移除 → 其 `K'` 不再下发，且 `L_i`（若有）作废 |

## 8. 安全属性声明

- **机密性（主威胁）**：仅持旧握手包、未进网的外部攻击者读不到 LAN → 拿不到 `K'`。✅
- **机密性（强化）**：已持旧 `K` 的入网攻击者，因 `K'` 经 `DSecret_i` 加密，仍拿不到。✅（需阶段 0 注册）
- **前向隔离**：旧握手包在轮换后失效，需每个周期重新抓包+爆破 → 攻击成本按周期倍增。✅
- **老设备隔离**：`L_i` 被爆不影响主网络 `K`。✅

## 9. 实现注意

- 生产环境 `Enc/Dec` **必须**为 AES-256-GCM，密钥 `HKDF-SHA256(DSecret_i)`；本仓库 `prototype/` 为演示使用标注清晰的 SHA-256 密钥流密码，**不得用于生产**。
- `DeviceID` 优先用设备身份公钥指纹，避免手机 MAC 随机化破坏绑定。
